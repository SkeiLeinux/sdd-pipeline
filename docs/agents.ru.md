# Работа с агентом

[English version](agents.md)

## Из чего состоит набор

| Часть | Где | Роль |
|---|---|---|
| Правила | `AGENTS.md` | загружаются всегда; короткие и жесткие |
| Скиллы | `.agents/skills/<имя>/SKILL.md` | по одному шагу пайплайна: параметры, что читать, что делать, чего нельзя, самопроверка, ответ |
| Субагенты | `.agents/subagents/<имя>.md` | запускают скрипты в своем контексте, исправляют механическое, возвращают короткий отчет |
| Шаблоны | `templates/` | структура каждого артефакта |
| Пример | `examples/LIB-1-book-reservations/` | форма, которую нужно повторять |

`.agents/` - единственный источник правды. Папки инструментов (`.claude/`, `.kilo/`, `.opencode/`) только адаптируют его.

## Настройка под инструмент

| Инструмент | Правила | Скиллы | Субагенты |
|---|---|---|---|
| Claude Code | `CLAUDE.md` подключает `AGENTS.md` | `.claude/skills/` - генерирует `python tools/sync_agents.py` | `.claude/agents/` |
| Codex | `AGENTS.md` | `.agents/skills/` | нет - агент сам выполняет инструкции субагентов |
| Kilo Code | `AGENTS.md` | `.agents/skills/` | `.kilo/agents/` |
| OpenCode | `AGENTS.md` | `.agents/skills/` | `.opencode/agents/` |
| Любой другой | укажите ему `AGENTS.md` | назовите файл скилла в запросе | агент сам выполняет `.agents/subagents/*.md` |

Форматы этих инструментов меняются. После настройки попросите агента "перечисли доступные скиллы и субагентов": должно быть десять скиллов `sdd-*` и `sdd-check`, `sdd-source`. Обертки в `.kilo/agents/` и `.opencode/agents/` используют формат `permission` (edit, bash, task); новым версиям инструментов может понадобиться другая шапка.

`.claude/settings.json` для Claude Code разрешает скрипты пайплайна и запрещает правку снимка.

## Запуск скилла

- Называйте его явно: "sdd-domain LIB-1 service-reservations" или слеш-командой, если инструмент это поддерживает.
- Один скилл - одна новая сессия.
- Читайте результат. Это черновик; на ревью уходит только то, что прочитал владелец.

## Шпаргалка запросов

| Шаг | Что сказать (каждый раз в новой сессии) |
|---|---|
| Прием | "sdd-intake: задача PAY-42, название Refunds, вход path/to/brd.md, источник BRD v3 из вики, владелец Анна" |
| Карта | "sdd-map features/PAY-42-refunds" |
| Утверждение карты | "Утверждаю карту с одной правкой: объединить ui-a и ui-b. Запиши в manual.md и пересобери срезы." |
| Домен | "sdd-domain features/PAY-42-refunds service-refunds" |
| Влияние | "sdd-impact features/PAY-42-refunds, существующий код в ../payments-service" |
| Контракты | "sdd-contracts features/PAY-42-refunds" |
| План | "sdd-plan features/PAY-42-refunds" |
| Спецификация | "sdd-spec features/PAY-42-refunds SPEC-06" |
| Ревью | "sdd-review features/PAY-42-refunds SPEC-06" |
| Ответы | "sdd-decide features/PAY-42-refunds: Q-003 - да, частичный возврат разрешен (BA, письмо 2026-11-05)" |
| Новая версия | "sdd-update features/PAY-42-refunds, новый вход source/import/brd-v4.md, BRD v4" |
| Проверка | "@sdd-check scope features/PAY-42-refunds, mode report" или "... mode gate ready" |

## Субагенты

| Субагент | Скрипт | Режимы | Исправляет сам | Возвращает |
|---|---|---|---|---|
| `sdd-check` | `tools/check.py` | `fix`, `report`, `trace`, `gate contracts`, `gate ready`, `regression` | кириллицу в ID, даты, регистр статусов, комментарии шаблона, физические типы данных | что исправил и что осталось, с подсказками |
| `sdd-source` | `tools/new_feature.py`, `tools/snapshot.py`, `tools/slices.py` | `new`, `snapshot`, `update`, `slices` | ничего руками | сводку снимка, таблицу изменений, ошибки срезов |

Вызов вручную: "@sdd-check scope features/LIB-1-book-reservations, mode report".

## Поведение модели, к которому надо быть готовым

1. **Уверенная выдумка** - главный риск: правдоподобное имя поля, код ошибки или статус без источника. Защита: правило "не выдумывать", маркеры `[?Q-NNN]`, вопросы с полем "Blocks", ворота и ревьюеры, которые ищут именно это.
2. **Многословность** заполняет контекст. Защита: скрипты в субагентах, новая сессия на скилл, срезы вместо всего документа.
3. **Потерянные строки** длинных таблиц. Защита: скиллы требуют сверить число требований с числом строк таблицы.
4. **Уход от шаблона.** Защита: шаблон и пример в контексте; скрипт сообщает о пропущенных разделах.

Температура: 0-0.3 для анализа и спецификаций, если инструмент позволяет; в обертках субагентов стоит 0.1.

Полезная калибровка на новой модели: дважды разобрать один и тот же домен в новых сессиях и сравнить требования.

## Типовые сбои

| Сбой | Как заметить | Что делать |
|---|---|---|
| Выдуманное поле, код, статус | нет источника в срезе, решениях или документации | искать в первую очередь на ревью; заменить на `[?Q-NNN]` |
| Потерянные строки таблицы | требований меньше, чем строк в таблице источника | перезапустить домен, попросив разбирать диапазонами строк |
| Сбился формат | коды `section`, `req-cols`, `plan-table` | новая сессия; убедиться, что шаблон и пример прочитаны |
| Пересказал тексты интерфейса | расходятся с источником | копировать из среза; проверять на ревью |
| Сам запускает скрипты или пропускает проверку | в ответе нет отчета `sdd-check` | назвать субагента явно; проверить, что инструмент его видит |
| Субагент спрашивает разрешение на каждую правку | запросы на файлы в `features/` | шаблоны путей в обертке не совпадают с форматом путей инструмента |
| Зацикливается | ответ растет без результата | остановить, сузить шаг, новая сессия |

## Полевая проверка

Набор прогнан от начала до конца новыми сессиями агента на синтетическом BRD в 120 строк с заложенными ловушками (два срока на одно решение, лимиты "по городу" без списка, статус, который ставится в два разных момента, не указана валюта). Каждый шаг получал только репозиторий и однострочный запрос из шпаргалки. Шаги: прием, карта, все 10 доменов, контракты, план, одна спецификация метода, ее ревью, применение двух ответов.

- Ловушки пойманы: карта отметила их в "Watch:", домены превратили их в вопросы, а не выбрали сторону, разрешил их только ответ владельца.
- Итог: 124 требования, 44 вопроса, 22 контракта, 29 единиц в плане, 0 ошибок проверки на каждом шаге.
- Ревью спецификации нашло настоящие дефекты проектирования, пропущенные автором (блокировка на время удаленных вызовов, молча решенный открытый вопрос, потеря уведомления при сбое).
- Каждый агент сообщал, где инструкции неясны; эти места исправлены: направление ребер, утверждение карты, противоречия, шум стадии плана в воротах контрактов, что читать при написании и ревью спецификаций, новые интерфейсы в ответах. Проверка получила правила `link-file`, `q-blocks-marker` и `table-cols`.

## Что не поручать агенту

Выбор между вариантами архитектуры (сравнение подготовить может), разрешение противоречий в источнике, изменение согласованных спецификаций без владельца, реальные персональные данные.

## Как улучшать набор

Скиллы и инструкции субагентов - это код: меняйте их через pull request с описанием, какой сбой исправлен. Удачный результат, прошедший согласование, стоит сохранить как пример. Новая механическая проверка - в `tools/check.py` с кодом правила и тестом в `tools/tests/`; если ее безопасно исправлять автоматически - строка в таблице "fix yourself" у `sdd-check`. После правки скиллов - `python tools/sync_agents.py`.
