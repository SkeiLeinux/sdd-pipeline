# Working with the agent

[Русская версия](agents.ru.md)

## How the kit is built

| Piece | Where | Role |
|---|---|---|
| Rules | `AGENTS.md` | always loaded; short and strict |
| Skills | `.agents/skills/<name>/SKILL.md` | one pipeline step each: parameters, what to read, what to do, what never to do, self-check, answer |
| Subagents | `.agents/subagents/<name>.md` | run scripts in their own context, fix mechanical issues, return a short report |
| Templates | `templates/` | the structure of every artifact |
| Example | `examples/LIB-1-book-reservations/` | the form to imitate |

`.agents/` is the single source of truth. Tool folders (`.claude/`, `.kilo/`, `.opencode/`) only adapt it.

## Setup per tool

| Tool | Rules | Skills | Subagents |
|---|---|---|---|
| Claude Code | `CLAUDE.md` imports `AGENTS.md` | `.claude/skills/` - generated by `python tools/sync_agents.py` | `.claude/agents/` |
| Codex | `AGENTS.md` | `.agents/skills/` | none - the agent follows the subagent instructions itself |
| Kilo Code | `AGENTS.md` | `.agents/skills/` | `.kilo/agents/` |
| OpenCode | `AGENTS.md` | `.agents/skills/` | `.opencode/agents/` |
| Anything else | point it to `AGENTS.md` | name the skill file in the request | the agent follows `.agents/subagents/*.md` itself |

Formats of these tools change. After setup, ask the agent to "list the available skills and subagents": you should see ten `sdd-*` skills and `sdd-check`, `sdd-source`. Wrappers in `.kilo/agents/` and `.opencode/agents/` use the `permission` format (edit, bash, task); newer tool versions may need a different header.

Claude Code's `.claude/settings.json` allows the pipeline scripts and denies edits of the snapshot.

## Running a skill

- Name it explicitly: "sdd-domain LIB-1 service-reservations", or as a slash command where the tool supports it.
- One skill - one fresh session.
- Read what it produced. The output is a draft; only what its owner has read goes to review.

## Subagents

| Subagent | Script | Modes | Fixes itself | Returns |
|---|---|---|---|---|
| `sdd-check` | `tools/check.py` | `fix`, `report`, `trace`, `gate contracts`, `gate ready`, `regression` | Cyrillic in IDs, dates, case of statuses, template comments, physical data types | what it fixed and what is left, with hints |
| `sdd-source` | `tools/snapshot.py`, `tools/slices.py` | `snapshot`, `update`, `slices` | nothing by hand | snapshot summary, changes table, slice errors |

Call manually: "@sdd-check scope features/LIB-1-book-reservations, mode report".

## Model behaviour to plan for

1. **Confident invention** is the main risk: a plausible field name, error code or status with no source. Defences: the "do not invent" rule, `[?Q-NNN]` markers, questions with "Blocks", gates, and reviewers looking for exactly this.
2. **Verbosity** fills the context. Defences: scripts in subagents, a fresh session per skill, slices instead of the whole document.
3. **Lost rows** in long tables. Defence: skills require comparing the number of requirements with the number of table rows.
4. **Style drift** from the template. Defence: templates and the example in context; the checker reports missing sections.

Temperature: 0-0.3 for analysis and specs if your tool lets you set it; subagent wrappers use 0.1.

A useful calibration on a new model: run the same domain twice in fresh sessions and compare the requirements.

## Typical failures

| Failure | How you notice | What to do |
|---|---|---|
| Invented field, code or status | no source in the slice, decisions or docs | the top thing to look for in review; replace with `[?Q-NNN]` |
| Lost table rows | fewer requirements than rows in the source table | rerun the domain, asking for row ranges |
| Wrong format | `section`, `req-cols`, `plan-table` codes | fresh session; make sure the template and example were read |
| Retold interface texts | differ from the source | copy from the slice; check in review |
| Runs the scripts itself or skips the check | no `sdd-check` report in the answer | name the subagent explicitly; check the tool sees it |
| Subagent asks permission for every edit | prompts on files in `features/` | path patterns in the wrapper do not match the tool's path format |
| Loops | the answer grows without progress | stop, narrow the step, new session |

## What not to hand to the agent

Choices between architectures (it may prepare a comparison), resolving contradictions in the source, changing approved specs without the owner, real personal data.

## Improving the kit

Skills and subagent instructions are code: change them through pull requests that say which failure the change fixes. A good result that passed approval is worth keeping as an example. A new mechanical check goes into `tools/check.py` with a rule code and a test in `tools/tests/`; if it is safe to fix automatically, add it to the "fix yourself" table of `sdd-check`. After editing skills run `python tools/sync_agents.py`.
